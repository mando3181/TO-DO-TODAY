# مَسار — نظام متابعة الإقفالات والمهام المالية

نظام ويب لمتابعة عمل الإدارة المالية بهيكل **المدير المالي ← رؤساء الأقسام ← المحاسبين**:

- الإقفالات اليومية: الإيرادات، وحركة البنوك، والصندوق، والمشتريات، والمصاريف، والعهد.
- الاعتماد والإرجاع من رؤساء الأقسام.
- المهام وحجم الإنجاز ومؤشر الأداء لكل محاسب.

الموقع ملف HTML واحد يُستضاف مجاناً على **GitHub Pages**، والبيانات المشتركة وتسجيل الدخول على **Firebase** (مجاني لفرق العمل الصغيرة والمتوسطة).

## محتويات المجلد

| الملف | وظيفته |
|---|---|
| `index.html` | النظام كاملاً |
| `config.js` | إعدادات الاتصال بـ Firebase وبريد المدير المالي |
| `firestore.rules` | قواعد حماية البيانات (تُنسخ إلى Firebase) |
| `README.md` | هذا الدليل |

---

## 1) التجربة السريعة (بدون أي إعداد)

افتح `index.html` في المتصفح مباشرة. يعمل النظام في **الوضع المحلي**، واضغط «تحميل بيانات تجريبية» لترى النظام وهو يعمل.

> في الوضع المحلي تُحفظ البيانات في متصفحك فقط ولا يراها أحد غيرك. هو مناسب للتجربة، لا للعمل الفعلي مع الفريق.

---

## 2) إنشاء مشروع Firebase (حوالي 10 دقائق، مرة واحدة)

1. ادخل إلى <https://console.firebase.google.com> بحساب Google، واضغط **Create a project**. سمِّه مثلاً `masar-finance`. يمكنك إيقاف Google Analytics.
2. **تفعيل تسجيل الدخول:**
   - من القائمة اختر **Build ← Authentication ← Get started**.
   - من تبويب **Sign-in method** فعّل **Email/Password**. فعّل الخيار الأول فقط، ثم **Save**.
3. **إنشاء قاعدة البيانات:**
   - من **Build ← Firestore Database ← Create database**.
   - اختر الموقع الأقرب لكم، مثلاً `me-central2 (Dammam)`. **لا يمكن تغييره لاحقاً.**
   - اختر **Start in production mode**.
4. **قواعد الحماية:**
   - داخل Firestore افتح تبويب **Rules**.
   - احذف الموجود، والصق محتوى ملف `firestore.rules`.
   - **غيّر** `cfo@example.com` إلى بريدك أنت (المدير المالي) بأحرف صغيرة.
   - اضغط **Publish**.
5. **ربط الموقع:**
   - من ⚙️ **Project settings ← General** انزل إلى **Your apps** واضغط أيقونة الويب `</>`.
   - سمِّ التطبيق `masar` (لا تفعّل Firebase Hosting)، ثم **Register app**.
   - ستظهر لك قيم `firebaseConfig`. انسخها.

## 3) تعبئة ملف `config.js`

افتح `config.js` واملأه هكذا، بالقيم التي نسختها في الخطوة السابقة:

```js
window.MASAR_CONFIG = {
  ownerEmail: "cfo@yourcompany.com",
  firebase: {
    apiKey: "AIza...",
    authDomain: "masar-finance.firebaseapp.com",
    projectId: "masar-finance",
    storageBucket: "masar-finance.appspot.com",
    messagingSenderId: "1234567890",
    appId: "1:1234567890:web:abc123"
  }
};
```

> قيم `firebaseConfig` ليست كلمات سر، ونشرها في GitHub أمر طبيعي. الحماية الفعلية تأتي من قواعد `firestore.rules` التي لا تسمح إلا للموظفين المضافين في النظام.

## 4) الرفع على GitHub Pages

**الطريقة الأسهل، من المتصفح:**

1. ادخل إلى <https://github.com/new> وأنشئ مستودعاً باسم `masar` مثلاً.
   - اجعله **Public**، لأن GitHub Pages المجاني يتطلب ذلك. البيانات نفسها ليست في المستودع، بل في Firebase.
2. اضغط **uploading an existing file**، واسحب الملفات الأربعة، ثم **Commit changes**.
3. من **Settings ← Pages**:
   - في **Source** اختر **Deploy from a branch**.
   - في **Branch** اختر `main` والمجلد `/ (root)`، ثم **Save**.
4. بعد دقيقة أو اثنتين يظهر رابط موقعك، مثل `https://USERNAME.github.io/masar/`.

**أو من سطر الأوامر:**

```bash
git init
git add .
git commit -m "مسار: نظام الإقفالات والمهام المالية"
git branch -M main
git remote add origin https://github.com/USERNAME/masar.git
git push -u origin main
```

## 5) السماح لدومين GitHub في Firebase (مهم)

من **Authentication ← Settings ← Authorized domains ← Add domain** أضف `USERNAME.github.io` (بدون `https://` وبدون `/masar`).

بدون هذه الخطوة لن يعمل تسجيل الدخول من الموقع المنشور.

## 6) التشغيل لأول مرة

1. افتح رابط الموقع، واضغط **إنشاء حساب جديد** ببريد المدير المالي (`ownerEmail`).
2. افتح رسالة التأكيد في بريدك، واضغط الرابط، ثم ارجع واضغط **أكّدت بريدي — متابعة**.
   - إن لم تجد الرسالة فابحث في مجلد الرسائل غير المرغوب فيها.
3. من **الهيكل التنظيمي** أضف نفسك بدور **المدير المالي** وبنفس البريد.
4. أضف الأقسام ورؤساءها والمحاسبين. **بريد كل موظف إلزامي**، لأنه بريد دخوله.
5. من **إعداد الإقفال** ابنِ مصفوفة الإقفال واضبط المواعيد.
6. أرسل رابط الموقع للفريق، ليضغط كل موظف **إنشاء حساب جديد** بنفس البريد المسجّل له ثم يؤكد بريده.

الشرح الكامل لطريقة العمل اليومية موجود في صفحة **دليل الاستخدام** داخل النظام.

## التكلفة وحدود الخطة المجانية

خطة Firebase المجانية (Spark) تتيح يومياً حوالي:

- 50,000 عملية قراءة.
- 20,000 عملية كتابة.
- 1 جيجابايت تخزين.

هذا يكفي فريقاً من 20 إلى 30 موظفاً في الاستخدام المعتاد. ويعمل النظام بذاكرة مؤقتة في المتصفح لتقليل القراءات.

إذا ظهرت رسالة «تم تجاوز الحصة اليومية» فالخيار هو الترقية إلى خطة **Blaze** (الدفع حسب الاستخدام). تكلفتها عادة بضعة دولارات شهرياً لهذا الحجم.

## النسخ الاحتياطي

- من **إعداد الإقفال ← البيانات والنسخ الاحتياطي ← تنزيل نسخة احتياطية** يُنزَّل ملف JSON بكل البيانات. يُنصح بتنزيل نسخة شهرياً.
- الاسترجاع من نفس المكان، وهو متاح للمدير المالي فقط.

## تحديث النظام لاحقاً

عدّل `index.html` ثم ارفعه من جديد إلى المستودع (Upload files أو `git push`). يتحدث الموقع خلال دقائق، ولا تتأثر البيانات لأنها محفوظة في Firebase.

## الأمان باختصار

- لا يقرأ البيانات أو يكتبها إلا من سجّل الدخول **وأكّد بريده** **وكان بريده مضافاً في الهيكل التنظيمي**. قائمة البريد المسموح يحدّثها النظام تلقائياً عندما يفتحه المدير المالي.
- حذف الموظف من الهيكل يوقف دخوله تلقائياً عند أول فتح للنظام من حساب المدير المالي.
- توزيع الصلاحيات بين الأدوار (المحاسب، رئيس القسم، المدير المالي) تطبّقه واجهة النظام.

## حل المشكلات

| المشكلة | الحل |
|---|---|
| «حسابك غير مفعّل بعد» | تأكد أن بريد الموظف مكتوب في بطاقته في الهيكل التنظيمي، وأن المدير المالي فتح النظام بعد الإضافة |
| لا يعمل تسجيل الدخول على رابط GitHub | أضف `USERNAME.github.io` في Authorized domains (الخطوة 5) |
| «تسجيل الدخول بالبريد غير مفعّل» | فعّل Email/Password في Authentication (الخطوة 2) |
| المدير المالي نفسه لا يستطيع الدخول | تأكد أن بريده مطابق تماماً في `config.js` وفي `firestore.rules`، بأحرف صغيرة |
| لم تصل رسالة تأكيد البريد | افحص الرسائل غير المرغوب فيها، أو اضغط «إعادة إرسال رسالة التأكيد» |
